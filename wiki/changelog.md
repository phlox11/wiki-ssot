# Changelog

Record only current-contract changes here: product-contract changes, significant architecture decisions, invariant changes, large reconciles, and schema or process changes. Git remains the source of truth for ordinary change history.

- Initial wiki established: engine, enforcement rails, and the self-describing pages.
- Fresh-context reconciliation promoted from advisory prose to a required, HEAD/bundle-bound attestation guard with explicit reviewer trust policy, downstream integration checks, and trusted GitHub reference enforcement.
- Fresh-context actor separation made deployment-specific: solo repositories may use the PR author's authenticated publisher for a separate session's report, while teams can require a distinct reviewer actor.
- Fresh-context review made risk-selectable from trusted changed-file, invariant, conflict, and current-page-removal signals while preserving all-PR behavior for existing configurations.
- Fresh-context reconciliation moved before PR creation through `wiki:review-preflight`; Drafts now skip the expected attestation failure, findings must be actionable, and merge-base invariant risk signals survive kind changes.
- The Ready-only GitHub check was renamed from `wiki-fresh-context` to `wiki-review-attestation` to make clear that CI validates a precomputed proof and does not perform the semantic review; required-check protection migrates through a no-gap old-plus-new transition.
- Fresh-context findings became structured: a version 2 report states each finding's scope, controlling authority, evidence, acceptance criteria, and disposition, a disposition pointing elsewhere must name its conflict or follow-up, and a PASS may not carry an unresolved finding — so a finding can be tracked instead of forcing every discrepancy into the current change. Bundle content is now version-bound against the merge-base engine rather than byte-frozen: new reviewer guidance governs the PRs after the one that introduces it.
- The toolkit became separately distributable from the repository that develops it. A generated `kit/` tree is now the copy-paste unit, split into kit-owned files that an upgrade replaces, seed files an upgrade never touches, and reference files that are read from the kit checkout and never delivered at all. A manifest of per-file hashes lets `kit-sync` tell an untouched file from a locally edited one and refuse to overwrite the latter; the manifest advances per file so one unresolved conflict cannot freeze the rest, and `--accept` records a hand-merged file so the conflict terminates instead of recurring forever. Links to pages only this repository has are stripped from the shipped `AGENTS.md` and `wiki/WORKFLOW.md` through `kit:exclude` regions, while rules that hold downstream stay in.
- Every rule about `kit/` became opt-in through `publishesKit`. The engine ships verbatim inside its own distribution, so an unconditional exemption travelled with it and silently disabled the wiki rails over any adopting repository's `kit/` directory, while the shipped `wiki:kit` command would overwrite whatever that project kept there. The exemption now applies in the publishing repository only, as a `kit/` path prefix that excludes the hand-written `kit/README.md` — which puts that file back under the link check — with the separate `wiki:kit --check` orphan scan keeping a hand-added path from hiding behind the prefix.
- Disposition legality became a contract rather than reviewer discretion: a fixed classification-to-disposition table refuses to retire a candidate regression or a declared contract violation by deferral, confines `recorded` to a suggestion, and keeps an undecided product question in a conflict. A disposition naming a conflict is now resolved against the open conflicts at the reviewed HEAD and must agree on at least one affected page the finding also scopes, on the conflict type where the classification implies one, and on `origin: baseline` where the classification says the problem predates the change — so a finding naming no page cannot be tracked by a conflict, and a finding cannot be filed as pre-existing while the conflict it names admits the change introduced it.
- Proposal backlogs became structured, validated repository work graphs. A no-query `wiki:work` command and generated work queue now derive ready/waiting state, expose blockers, dependencies, evidence, owners, and open conflicts, recommend only active or ready work deterministically, and hand selected IDs to authority-labelled `wiki:context -- --work`.
