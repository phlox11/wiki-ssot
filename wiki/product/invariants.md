# Invariants

These hold for every change to this repository.

- **Remaining work is discoverable without prior node knowledge.** Proposal work records form one validated repository-wide graph with unique IDs, current-page context targets, legal lifecycle fields, optional `agent | human | either` executors, acyclic known dependencies, blockers/reasons, and durable done evidence. Executor is independent from state and omission normalizes to `agent`. `wiki:work` requires no query, derives ready/waiting state from the complete graph before filtering, includes open conflicts, keeps human work visible, and recommends only active or ready `agent`/`either` work by explicit state, priority, and ID; human-exclusive work is discovery-and-handoff only. The provider-neutral agent entrypoint must supply affirmative clause shapes routing session start through the wiki index, current status, and invariants; generic remaining-work intent through the no-query queue; human work through reporting and handoff without assumed authority; returned selections through focused work context; and topic work through search/context without presenting non-current pages as current authority. Common explicit directive negations invalidate the clause they contradict; the deterministic check is not a general prose interpreter. Default selected-work and complete-match topic context expose status, authority, Wiki path, exact source declarations, mandatory `always` source paths, bounded catalog declaration/reason/count/bytes/digest descriptors, page-local open conflicts, stable body digests, and focused commands in compact text and JSON; explicit `--full` preserves every expanded source and exhaustive body. Partial-only topic context returns every deterministically ordered candidate as compact metadata before the caller chooses focused expansion, without stop-word, weighting, or result-limit rules that could silently hide controlling authority or an open conflict. The authoritative read order remains invariant → conflict → current page → mandatory authority source; owning proposals and directly matched proposed, deprecated, archived, or resolved-conflict pages remain explicitly separate non-current rationale outside that order. A reusable selected-work handoff may omit bodies and catalog paths only when it binds the exact committed HEAD, selector, canonical metadata, base and merge-base, controlling pages, conflicts, individual mandatory source digests, catalog set digest/count/bytes, full context, and read order; any mismatch invalidates it as a unit, and it never replaces direct inspection of listed authority and required sources. Executor, recommendation, and context reuse never grant external-write, destructive, credential, or human authority.
- **Deterministic enforcement, pre-PR risk-scoped semantic reconciliation.** GitHub never has to invoke an LLM or run the Wiki engine. Before opening a PR, trusted policy deterministically decides whether a change requires independent semantic reconciliation from reasoned changed-file rules, actual kit-owned file membership, merge-base/HEAD affected invariants, affected conflicts, and current-page removals. When required, the authoring agent gives the exact bundle to a context-isolated reviewer, reconciles actionable findings, and reaches local PASS before publication. The canonical local result binds the clean committed HEAD, base and merge base, semantic metadata, deterministic checks, configured project-check argv and outcomes, warnings, review bundle/report identity, and its own digest; a publisher must reject malformed, dirty, stale, or remote-head-mismatched evidence before any status write. Bundle compaction may store identical authority/invariant/conflict content once only when a focused manifest preserves every role against the same digest. Its source roles are non-exclusive and must retain every changed primary source, directly affected authority source, relevant test, conflict, and supporting declaration with independently validated provenance and content bindings; a broad glob is never permission to omit a required input. Local publication does not self-attest or relax review selection, and version 2 local-status claims procedural context isolation rather than authenticated actor separation.
- **Current pages trace to real sources without forcing broad rereads.** A `status: current` page requires at least one existing `sources` entry and, when it uses catalog context, at least one `always` anchor. `always` versus reasoned `catalog` changes compact reading only: mapping, coverage, verification hashes, drift, impact, conflicts, and full expansion retain every matched source. Legacy omission remains `always`; a newly added or changed declaration must classify itself explicitly. A missing source path, invalid declaration intent, or stale hash fails the build. Scope audit explains counts, bytes, fan-out, causes, and base deltas but never fails merely because a numeric size or selection ratio is large.
- **Ambiguity is a conflict, not an invention.** When intent is unclear, or code and wiki disagree in a way that could change behavior, the change opens a `wiki/conflicts/open/**` record instead of guessing.
- **Implementation changes cannot claim `wiki_action: none`.** Any change to a non-doc, non-generated source must update or explicitly verify its pages.
- **Installation and upgrade converge through one safe loop.** The same deterministic apply entrypoint handles `new`, `adopt`, and `upgrade`, then regenerates and checks Wiki/code synchronization. It owns generic kit files, declared integration blocks, `wiki:*` package scripts, and compatible toolkit dependencies; it preserves project-owned policy, host lifecycle scripts, host workflows, and content outside managed blocks. New installations receive version 2 local-status configuration and no active GitHub workflow. Existing version 1 or customized workflows are never silently deleted when the upstream kit stops shipping them; doctor requires explicit command migration and reconciliation. Apply performs no Git publication and no model call. Unsafe merges return explicit work, and a copied toolkit with no source-backed current page or maintained coverage is not reported as complete. Dry-run preserves bytes without omitting bootstrap semantics: it returns the same bootstrap findings for incomplete new/adopt targets, uses `preview` only for a safe bootstrapped plan, and reserves `ready` for a mutating run whose installed checks passed.
- **Portable module growth is bounded by owned contracts, not repository size.** Each kit-owned TypeScript path names one contract. Caps: 1,000 LF lines/64 KiB; `cli.ts` 250 lines; sole `review-bundle.ts` exception 1,000 lines/68 KiB. Unclassified or oversized paths fail with split, exception, or owner guidance; repository totals and publisher measurements are not gates.
- **The authoring context cannot self-attest when review is required.** It owns reconciliation and may modify code/wiki/tests, but a separate context-isolated reviewer creates the report and never modifies the reviewed HEAD. `NEEDS_RECONCILE` must identify the discrepancy, controlling authority, required change, and acceptance criteria. A version 2 finding states this as structure: scope binding it to the reviewed change, controlling authority, evidence, closable acceptance criteria, and a disposition, where a disposition pointing elsewhere names the conflict or follow-up it points at. A `PASS` may not carry an `unresolved` finding, and a disposition pointing elsewhere must name its target, so a finding that states a contract is retired only by fixing it, tracking it, or dismissing it with a recorded reason. Which dispositions retire which classification is fixed rather than discretionary: a break this candidate caused, or a contract the PR itself declares, admits no deferring disposition and is closed only by fixing it; an undecided product question may be fixed or tracked in a conflict but never dismissed or deferred to a follow-up; and `recorded`, which retires nothing, is limited to a `suggestion`. A disposition naming a conflict must name one open at the reviewed HEAD carrying the conflict type its classification implies where one is implied, declaring `origin: baseline` whenever the classification says the problem predates the candidate, and sharing a page with the finding's scope — which a finding naming no page cannot do. The author writes that `origin` and the reviewer writes the classification independently, so a finding cannot be filed as pre-existing while the conflict it names admits the change introduced it. Whether the reviewer classified honestly in the first place remains reviewer judgement. Ambiguity becomes a conflict or owner decision rather than a speculative loop. Version 2 proves exact report bindings and procedural separation; teams requiring a distinct authenticated actor retain version 1 or provide another external enforcement path.
